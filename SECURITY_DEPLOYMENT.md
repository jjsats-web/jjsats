# Security Deployment

This release replaces raw PIN cookies with signed server sessions, hashes PINs in PostgreSQL, and stores quote pricing as a database snapshot.

## Required deployment steps

1. Apply the SQL migrations in `supabase/migrations` before deploying the application.
2. Set `PIN_SESSION_SECRET` to a long random server-only value in the production environment. The application temporarily falls back to `SUPABASE_SERVICE_ROLE_KEY` for existing deployments, but a dedicated secret is recommended.
3. Set `APP_BASE_URL` to the exact externally reachable application URL. Telegram approval links use only this value and never trust a request header.
4. Deploy the application. Existing raw PIN sessions are intentionally invalidated, so every user must sign in again.
5. Regenerate types with `npm run gen:types` after applying the migrations if the Supabase CLI environment variables are available.

## Included database protections

- Bcrypt-hashed PINs and server-only RPC functions for PIN verification and changes.
- Persistent PIN attempt throttling: five failed attempts in five minutes lock the source IP for fifteen minutes.
- Direct Supabase access is revoked from browser roles for customers, products, quotes, approvals, and PINs; the app uses server-side APIs only.
- Stable, unique quote numbers generated by PostgreSQL.
- Quote pricing snapshots for subtotal, discount, VAT, and grand total.
- One active approval request per quote, with a five-minute re-request cooldown.
